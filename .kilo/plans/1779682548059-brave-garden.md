  - Business logic: California overtime (daily/weekly), lunch enforcement (30-60 min warnings), yesterday blocking, "complete" + adminNotes, audit trail (AuditViewer).

    - Admin: AdminPanel (user mgmt, corrections, bulk import), PayrollReports (CSV export), AuditViewer, PatternMetrics, CorrectionRequests.
  - Security: Firestore rules (v2) enforced per-role access + active flag. Admin-only delete. No hard delete logic yet.
  - Hosting/Config: firebase.json (us-west2, emulators ready), firebase.config.js (public keys committed — noted risk), existing firestore.rules + indexes.
  - Timezone references: mixed (browser default + some PST notes); prompt demands America/Los_Angeles standardization.
  - Existing operational docs: ONBOARDING_RUNBOOK, WEEK1_OPERATIONS, TIME_INTEGRITY_PLAN, TESTING_GUIDE, FINAL_CHECKLIST, several summaries.
  - Git: single `main` branch, clean. No worktrees or agent structure yet. .kilo/agent-manager.json exists but empty outside this session.
  - No Operation Hub, no PHP, no direct OrangeHRM/Kimai/TimeTrex code.

**Key Risks Identified (to be captured in QA doc later):**

## 2. Master Workflow (Direct Translation of User Prompt)

- Reads entire app only.
- Deliverable: PROJECT_AUDIT.md (stack, Firebase, pages, auth, roles, time calcs, reporting, rules, indexes, gaps).

**Architecture Agent (architecture/hr-time-structure)**
- Design-only (no code edits in Phase 1).

  - ARCHITECTURE_PLAN.md
  - FIRESTORE_DATA_MODEL.md
  - SECURITY_RULES_PLAN.md

**Clock Agent (feature/punch-clock)**
- Starts only after audit + architecture docs approved.
- Allowed folders: employee clock components, time entry services/helpers, clock business rules, related tests.
- Deliverable: working punch flow + CLOCK_FEATURE_NOTES.md
- Blocked from admin approval paths unless manager OK.

**Admin Agent (feature/admin-timesheets)**
- Improves review + correction (mandatory reason + audit entry per correction).
- Allowed areas: admin dashboard, timesheet UI, correction components, audit log helpers, tests.
- Deliverable: improvements + ADMIN_TIMESHEET_NOTES.md
- Cannot touch employee clock screen unless explicitly approved.

**HR Agent (feature/leave-holidays)**
- Plan-only in this scope.
- Deliverable: HR_LEAVE_HOLIDAY_PLAN.md (vacation, sick, unpaid, holidays, work week, expected hours, approval flow, payroll implications).

**QA/Security Agent (qa/testing-security)**
- Review-only unless manager approves functional changes.
- Deliverables:
  - QA_SECURITY_REVIEW.md
  - TESTING_CHECKLIST.md
  - LAUNCH_CHECKLIST.md

## 5. Safety & Compliance Rules (Must Become Part of Every Agent Context)

1. Never touch Operation Hub integration code or config.
2. Never delete any existing source file (src/ + public/ + scripts/) without explicit manager written approval in chat + commit message.
3. Never copy bulk logic from OrangeHRM/Kimai/TimeTrex repositories.
4. Default timezone = America/Los_Angeles for all calculations/storage/display.
5. Corrections always write to an audit collection (no in-place mutation only).
6. Time entries use soft states (active, corrected, voided, archived).
7. Employee phone experience remains ≤2 taps for clock in/out.
8. Every sub-agent produces a "files touched + summary" note before any merge request.
9. Manager is single source of truth for ownership matrix; any file touched by two agents triggers immediate pause.

## 6. Technical / Tooling Considerations

- **Agent Manager usage**: Each worktree = separate Kilo session/tab. Manager will use `task` tool or direct chat addressing ("@audit-agent") only after worktree is active.
- **Git hygiene**: Branches prefixed exactly (`planning/`, `audit/`, `architecture/`, `feature/`).
- Worktree root = `.kilo/worktrees/<slug>` (discourages accidental direct edits of src/ from wrong session).
- No run-script or emulator cross-talk; developers will still launch dev/emulators from main checkout or any chosen worktree (state should converge via docs).
- Firebase emulators can be leveraged by all agents for rules testing without changing production data.
- Linting/Typecheck: once any feature work begins (Phase 1), manager must require all agents invoke `npm run lint` + `npm run typecheck` (or equivalent) before PR/merge request.

## 7. Risk Register & Mitigations

- Risk: Accidental code leakage across worktrees → Mitigation: explicit per-agent glob ownership + manager diff review on every summary.
- Risk: Firebase key exposure → QA doc must flag; document rotation plan.
- Risk: Different agents disagree on Firestore collection names → Architecture agent owns final data model; others read-only reference it.
- Risk: Manager becomes bottleneck → Provide explicit short prompts + file ownership matrix so agents self-filter.
- Risk: Run scripts differ per worktree → Default: no run-script initially; dev must use node/npm commands directly with correct `import.meta.env`.
