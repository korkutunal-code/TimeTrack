## 2. Model Landscape Research (May 2026)

### 2.1 Kilo-Native Recommendations (from kilo.ai/docs)
- **Auto tiers** (`kilo-auto/frontier`, `kilo-auto/balanced`): 
  - `plan | general | architect | orchestrator | ask | debug` → `anthropic/claude-opus-4.7`
  - `build | explore | code` → `anthropic/claude-sonnet-4.6`
- **Agent Manager specifics**: Supports per-version model assignment in Multi-Version Mode (up to 4 parallel worktrees). Sub-agents via `task` tool inherit parent model unless overridden in config. Context-limit recovery favors long-context models (Gemini family). Experimental `agent_manager` tool enables chat-driven worktree spawning.
- **Philosophy**: Match model to role (orchestration vs. execution) and to cost/latency needs for parallel work.

### 2.2 Frontier Models for Agent Manager + Continuous/Long-Running Work
Key requirements for this codebase: complex domain reasoning (CA overtime + segments + audit invariants), long-horizon planning (multi-week feature branches), high instruction fidelity (never violate `AGENTS.md`), cost efficiency for parallel workers, durable state across sessions, self-correction on payroll math.

**Tier 1 – Best for Agent Manager Orchestration / Manager Role (2026-05)**
- **anthropic/claude-opus-4.7** (or `kilo-auto/frontier`): 
  - Strengths: Rigorous long-running reasoning, "dreaming" (cross-session memory refinement + self-improvement), "outcomes" (rubric-based self-correction), native multi-agent orchestration (lead + specialists on shared FS with full traceability). Excellent for enforcing invariants like timezone, audit reasons, soft deletes. 1M context. Highest fidelity for complex payroll/HR logic.
  - Evidence: Claude Managed Agents updates (May 2026), enterprise use at Harvey (legal), Netflix (log analysis), writing agents. Strong CursorBench/SWE-bench numbers for autonomous coding.
  - Cost: Higher (≈5/25 per M tokens). Use for manager, architect, debug, reviewer personas.
- **google/gemini-3.1-pro (or 3.5 Flash variants)**:
  - Strengths: Purpose-built "agent-first" model. Thought preservation across multi-turn, native sub-agent deployment (Antigravity harness), durable runtime (pause/resume for days via Agent Executor/ADK + Memory Bank), 4× faster + often <½ cost of peers. 1M+ context. Excellent for synthesis of large docs (Firestore rules, overtime calcs) and continuous background agents.
  - Evidence: Google DeepMind/Cloud blogs (May 2026) on long-running agents, Enterprise Agent Platform, Terminal-Bench/MCP Atlas leadership, real usage at Xero (multi-week tax workflows), Salesforce Agentforce.
  - Ideal for: Continuous work, large-context analysis, cost-sensitive parallel implementations.

**Tier 2 – Best for Parallel Worker / Implementation Agents**
- **anthropic/claude-sonnet-4.6**: Kilo default for `code/build/explore`. Balanced quality/cost. Great for feature implementation once architecture is locked.
- **google/gemini-2.5-flash or 3.1-pro**: Fast, cheap, long context. Perfect for Multi-Version Mode A/B tests (run 3–4 variants of a refactor in parallel worktrees and diff the results).
- **deepseek/deepseek-v4-pro (or Flash)**: Ultra-cheap frontier-class coding (MIT licensed variants). 29× cheaper than Opus in some benchmarks. Ideal for high-volume parallel experiments, test generation, or budget worker swarms. 1M context in Pro tier.
- **moonshotai/kimi-k2.x**: Strong multilingual/coding value; useful secondary option.

**Tier 3 – Specialized / Fallback**
- GPT-5.4 / o-series: Strong tool-use and professional workflow execution.
- OpenRouter / BYOK fallbacks for quota resilience.
- Local models (Ollama) for read-heavy review or non-sensitive tasks.

**Key Trade-offs for Continuous Work**:
- **Claude Opus 4.7 + Managed Agents features (dreaming/outcomes)**: Highest quality and self-improving memory for multi-week efforts (e.g., full payroll module overhaul). Best when the agent must "learn" the TimeTrack invariants over time.
- **Gemini long-running stack (ADK + Agent Executor + durable state)**: Superior for true 24/7-style background agents that pause/resume across days without losing context or burning tokens on idle polling. Cheaper sustained operation.
- **Hybrid (Kilo strength)**: Manager on Opus/kilo-auto/frontier (orchestration + dreaming), workers on Sonnet/Gemini/DeepSeek (execution + parallel experiments). Use Kilo's per-agent model overrides + Agent Manager Multi-Version Mode.
- **Cost Reality for Parallel**: Running 4 agents for a day on Opus is expensive. Strategy: Opus only for manager/planner/reviewer; Gemini/DeepSeek for implementation swarm.

**Sources** (May 2026): Kilo docs (model-selection, Agent Manager, models-and-providers), Google DeepMind/Cloud blogs on Gemini 3.5/ADK/Agent Executor, Claude Managed Agents announcements (dreaming, outcomes, multiagent), independent comparisons (HostAgentes, Leanware, VentureBeat on Qwen endurance), OpenRouter coding model benchmarks.

## 3. Recommended Configuration Strategy for TimeTrack

### 3.1 Role-Based Model Routing (Project + Global)
- **Manager / Orchestrator / Architect / Planner / Reviewer / Debug**: `anthropic/claude-opus-4.7` (or `kilo-auto/frontier`).
- **Implementation / Code / Explore / Build (workers)**: `anthropic/claude-sonnet-4.6` (primary) + `google/gemini-3.1-pro` (cost/long-context alternative) + `deepseek/deepseek-v4-pro` (budget parallel).
- **Fast / Summarization / Read-heavy audit**: `google/gemini-2.5-flash` or Kilo fast tier.
- **Fallback / Quota resilience**: DeepSeek or Gemini Flash via virtual provider.
- **Project-local overrides** (in `.kilo/kilo.json`): Define custom agents (`payroll-auditor`, `overtime-enforcer`, `firebase-rules-reviewer`) that hard-pin the above models and embed TimeTrack-specific instructions referencing `AGENTS.md`.

### 3.2 Agent Manager Continuous-Work Patterns
- Use **Multi-Version Mode** routinely for risky refactors (e.g., overtime calc changes): 1× Opus (gold standard), 1× Sonnet, 1× Gemini, 1× DeepSeek. Diff panel + human review of winner.
- **Sections** in Agent Manager: Organize by domain (`📁 Payroll Core`, `📁 HR Leave`, `📁 Security/Audit`, `📁 Infra/Staging`).
- **Setup/Run Scripts**: Auto-copy `.env*` (including Firebase emulator config), run `npm install`, start Vite + emulator if present, run `npm run lint` or targeted tests. Inject `WORKTREE_PATH` for isolation.
- **Long Sessions**: Raise compaction to 75% (already done globally in user's prior hardening). Use personas + `AGENTS.md` injection via `instructions` array.
- **Durable Patterns**: For multi-day work (e.g., "implement full leave approval flow + payroll export"), start in worktree, let agent "sleep" (close VS Code), resume later. Gemini's thought preservation + Claude dreaming help continuity.
- **Checkpoint + Human Gates**: Leverage existing merge-order discipline. Manager agent proposes PRs; human (or doc-agent persona) reviews before merge.

### 3.3 Project-Specific Enhancements
- **Personas** (`.kilo/personas/`):
  - `reviewer.md`: Read-only, enforces `AGENTS.md` (timezone, audit reasons, soft deletes, no client billing). Severity: INFO/WARN/BLOCK.
  - `planner.md`: Outputs only to `.kilo/plans/`. Breaks work into worktree-sized chunks, suggests model assignments, identifies rollback strategy.
  - `doc-agent.md`: Maintains `ARCHITECTURE_PLAN.md`, `CHANGELOG.md`, `docs/planning/*`, and updates `AGENTS.md` when invariants evolve.
  - `payroll-guardian.md` (new): Domain expert that cross-checks overtime math, segment logic, and audit invariants against `src/utils/overtimeCalculations.ts` and `dateHelpers.js`.
- **Setup/Run Scripts**:
  - `setup-script`: Copy env, `npm install` (root + any functions/), seed test users if emulator, verify Firebase emulators ready.
  - `run-script`: `npm run dev` (Vite) + emulator commands in background; per-worktree ports via `WORKTREE_PATH`.
- **Local `.kilo/kilo.json` extensions**:
  - Model overrides for custom agents.
  - Permission tightening (e.g., reviewer persona: edit only `.md` files).
  - Reference to `AGENTS.md` + new personas in `instructions`.
- **MCP / Tooling**: Leverage existing `@gannonh/firebase-mcp` (already in deps). Consider enabling Kilo's Firebase MCP globally for agents. Add GitHub MCP (with PAT) for PR workflow once hardened.
- **Cleanup**: Remove any stale worktree metadata; ensure `.kilo/` stays git-tracked for plans but runtime artifacts ignored.
