## Open findings (not yet fixed — next pass)
1. **Entry-access UX bug in TodayEntry** — when access blocked, form fields stay editable, only the submit button is disabled. Confusing. Should hide the form.
2. **`getAllTimeEntries` limit(500)** — payroll silently truncates once you have >500 entries. A pilot will hit this within a month.
3. **`getDay()` in `timeValidation.checkTimeAnomalies` and `scheduleHelpers.checkWrongDay`** — uses local TZ. Same root cause as the fix above; weekend check is wrong for non-UTC users.
4. **`calculateEstimatedHours` in TodayEntry** — `new Date(today).setHours(...)` mixes YYYY-MM-DD (UTC-anchored) with local-time setHours. For Turkey/Thailand users can produce `Invalid Date`.
5. **Two UIs stacked** — `ClockPunch` (newer, one-tap) renders ABOVE `TodayEntry` (older, multi-step). Should pick one for employees.
6. **LoginPage ephemeral toast** — error auto-dismisses in ~4s. A11y finding from the 2026-04-17 report, not addressed.
7. **`esModuleInterop` not enabled** in tsconfig — ts-jest advisory on every run. Trivial.
8. **No CI** — `npm test && npm run build` not on pre-merge.
9. **Firestore rules tests not re-run** since the original commit.
10. **`TodayEntry` "Start New Shift" race** — if user double-clicks, can re-archive a segment.
